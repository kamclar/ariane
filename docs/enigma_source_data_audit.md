## Rule tables implemented in code

The adapted ACMG/AMP classification combinations were checked against
Specifications Table 3. Two errors were repaired:

- two pathogenic Strong criteria now produce Likely Pathogenic, not Pathogenic;
- benign combinations involving Strong plus multiple Moderate/Supporting codes
  now reach Benign where specified.

## Reproducibility and startup policy

Table 4, Table 9, ST7, the complete ST2 splice-evidence snapshot and the exon-CNV evidence snapshot are generated by scripts in `scripts/` from the
official downloaded workbooks. Startup validation rejects truncated snapshots,
wrong row/column counts, missing required fields, unknown codes and inconsistent
exon references. The application does not silently continue with an incomplete
core ENIGMA table.

The PP4/BP5 source has an additional update check because the UCSC ENIGMA
track can change independently of the VCEP specification. The checker compares
the remote BigBed checksum with the pinned release. A changed file can only be
stored as an inactive candidate. Activation requires source and schema review,
a snapshot diff, review of threshold crossings, the complete test suite and
recorded expert approval.

Protein-level PS1 uses official ST7 P/LP records only to discover candidate
references. ST7 alone does not prove that a reference classification was
assigned using the VCEP specifications. Automatic application requires a
separately verified VCEP assertion or documented local VCEP reclassification,
an `eligible` versioned registry record, on-demand SpliceAI at most 0.1 for both
the reference and assessed variant, no damaging splice evidence in Table 9 or
complete ST2, provenance and dependency metadata.
Incomplete candidates are returned for manual review without points; excluded
candidates are shown with the exclusion reason and add no points.
